# 要件書

## はじめに

AWS上で動作するサーバーレス画像管理システム。管理者が画像をアップロード・管理し、一般公開された画像を誰でも閲覧できるWebアプリケーションです。

## 用語集

- **System**: 画像管理システム
- **System_Admin**: システム管理者（全ユーザーの画像を完全に管理可能）
- **Image_Manager**: 画像管理者（全ユーザーの画像の公開状態制御とダウンロードが可能）
- **Regular_User**: 一般ユーザー（自分の画像のみ管理可能）
- **Image**: システムで管理される画像ファイル（JPEG形式のみ）
- **Tag**: 画像に付与される分類用のラベル
- **Storage**: AWS S3などのクラウドストレージ
- **Metadata**: 画像に関連する情報（ファイル名、サイズ、アップロード日時、撮影日時、タグ、所有者等）
- **Admin_Screen**: 管理者用の画面（認証必須）
- **Viewer_Screen**: 一般公開用の閲覧画面（認証不要）

## 要件

### 要件1: 画像アップロード（管理画面）

**ユーザーストーリー:** 管理者として、画像をシステムにアップロードしたい。そうすることで、画像を安全に保存し管理できる。

#### 受け入れ基準

1. ユーザーが有効なJPEG画像ファイルを選択してアップロードボタンをクリックしたとき、THE System SHALL 画像をStorageに保存する
2. ユーザーが複数のJPEG画像ファイルを同時に選択したとき、THE System SHALL すべてのファイルを一括でアップロードする
3. ユーザーがフォルダを選択したとき、THE System SHALL フォルダ内のすべてのJPEG画像ファイルをアップロードする
4. ユーザーがJPEG以外のファイル形式をアップロードしようとしたとき、THE System SHALL エラーメッセージを表示し、該当ファイルのアップロードを拒否する
5. 画像がアップロードされたとき、THE System SHALL Metadataを自動的に生成し、所有者情報と共に保存する
6. アップロード中、THE System SHALL 各ファイルの進捗状況をユーザーに表示する
7. ファイルサイズが制限を超えている場合、THE System SHALL 該当ファイルのアップロードを拒否し、適切なエラーメッセージを表示する

### 要件2: タグ付け機能

**ユーザーストーリー:** 管理者として、画像にタグを付けたい。そうすることで、画像を分類し、検索しやすくできる。

#### 受け入れ基準

1. ユーザーが画像にTagを追加したとき、THE System SHALL TagをMetadataに保存する
2. ユーザーが画像からTagを削除したとき、THE System SHALL 該当するTagをMetadataから削除する
3. ユーザーが複数のTagを一つの画像に追加したとき、THE System SHALL すべてのTagを保存する
4. ユーザーが既存のTagを選択したとき、THE System SHALL オートコンプリート機能を提供する
5. Tagが入力されたとき、THE System SHALL 重複するTagの追加を防ぐ

### 要件3: 画像表示・一覧（公開画面）

**ユーザーストーリー:** 一般の訪問者として、公開されている画像を閲覧したい。そうすることで、公開されている画像を簡単に見ることができる。

#### 受け入れ基準

1. 訪問者がViewer_Screenにアクセスしたとき、THE System SHALL 指定件数の公開画像をサムネイル形式で表示する
2. 訪問者がページをスクロールしたとき、THE System SHALL 次の指定件数の画像を自動的に読み込み表示する
3. 訪問者がサムネイルをクリックしたとき、THE System SHALL 画像を拡大表示するモーダルビューを開く
4. 拡大表示中、THE System SHALL 画像の詳細情報（ファイル名、撮影日時、タグ等）を表示する
5. 拡大表示中、THE System SHALL 前後の画像に移動できるナビゲーション機能を提供する
6. 画像が存在しない場合、THE System SHALL 適切なメッセージを表示する
7. 画像の読み込み中、THE System SHALL ローディング表示を提供する
8. すべての画像が読み込まれたとき、THE System SHALL 読み込み完了を示すメッセージを表示する

### 要件4: 画像管理（管理画面）

**ユーザーストーリー:** 管理者として、アップロードした画像を管理したい。そうすることで、画像の整理や編集ができる。

#### 受け入れ基準

1. Regular_UserがAdmin_Screenにアクセスしたとき、THE System SHALL 自分がアップロードした画像のみを50件ずつページネーション形式で表示する
2. System_AdminがAdmin_Screenにアクセスしたとき、THE System SHALL すべてのユーザーの画像を50件ずつページネーション形式で表示する
3. Image_ManagerがAdmin_Screenにアクセスしたとき、THE System SHALL すべてのユーザーの画像を50件ずつページネーション形式で表示する
4. ユーザーがページネーションボタンをクリックしたとき、THE System SHALL 指定されたページの画像を表示する
5. ユーザーが画像を選択したとき、THE System SHALL 編集オプション（タグ編集、削除等）を表示する
6. System_AdminまたはImage_Managerが画像の公開状態を変更したとき、THE System SHALL Viewer_Screenでの表示状態を更新する
7. Regular_Userが自分の画像の公開状態を変更したとき、THE System SHALL Viewer_Screenでの表示状態を更新する
8. System_Adminが画像情報を編集したとき、THE System SHALL 変更をMetadataに反映する
9. Regular_Userが自分の画像情報を編集したとき、THE System SHALL 変更をMetadataに反映する
10. ユーザーが画像にチェックボックスを付けたとき、THE System SHALL 選択状態を管理する
11. ユーザーが一括削除ボタンをクリックしたとき、THE System SHALL チェックされた画像の削除確認ダイアログを表示する
12. ユーザーが一括削除を確認したとき、THE System SHALL チェックされたすべての画像を削除する
13. Regular_Userが他のユーザーの画像にアクセスしようとしたとき、THE System SHALL アクセスを拒否する
14. Image_Managerが画像の編集や削除を試みたとき、THE System SHALL 操作を拒否する
15. 画像の総件数が表示されているとき、THE System SHALL 現在のページ位置と総ページ数を表示する

### 要件5: 画像削除（管理画面）

**ユーザーストーリー:** 管理者として、不要になった画像を削除したい。そうすることで、ストレージ容量を節約し、整理された状態を保てる。

#### 受け入れ基準

1. ユーザーが単一画像の削除ボタンをクリックしたとき、THE System SHALL 確認ダイアログを表示する
2. System_Adminが任意の画像の削除ボタンをクリックしたとき、THE System SHALL 確認ダイアログを表示する
3. ユーザーが複数の画像をチェックして一括削除ボタンをクリックしたとき、THE System SHALL 選択された画像数を含む確認ダイアログを表示する
4. ユーザーが削除を確認したとき、THE System SHALL 選択された画像をStorageから完全に削除する
5. 画像が削除されたとき、THE System SHALL 関連するMetadataとTagも削除する
6. 削除が完了したとき、THE System SHALL 成功メッセージを表示し、現在のページを更新する
7. 削除中にエラーが発生した場合、THE System SHALL エラーメッセージを表示し、元の状態を維持する
8. Regular_Userが他のユーザーの画像を削除しようとしたとき、THE System SHALL 操作を拒否する
9. Image_Managerが画像を削除しようとしたとき、THE System SHALL 操作を拒否する
10. 一括削除中、THE System SHALL 削除進捗を表示する
11. 削除後にページが空になった場合、THE System SHALL 前のページに自動的に移動する

### 要件6: 画像ダウンロード（管理画面）

**ユーザーストーリー:** 画像管理者として、画像をダウンロードしたい。そうすることで、バックアップや外部利用ができる。

#### 受け入れ基準

1. System_Adminが画像のダウンロードボタンをクリックしたとき、THE System SHALL オリジナル画像をダウンロードする
2. Image_Managerが画像のダウンロードボタンをクリックしたとき、THE System SHALL オリジナル画像をダウンロードする
3. Regular_Userが自分の画像のダウンロードボタンをクリックしたとき、THE System SHALL オリジナル画像をダウンロードする
4. Regular_Userが他のユーザーの画像をダウンロードしようとしたとき、THE System SHALL 操作を拒否する
5. 複数の画像がチェックされているとき、THE System SHALL 一括ダウンロード機能を提供する
6. 一括ダウンロード時、THE System SHALL 画像をZIPファイルにまとめてダウンロードする
7. ダウンロード中、THE System SHALL 進捗状況を表示する
8. ダウンロードが完了したとき、THE System SHALL 成功メッセージを表示する

### 要件7: 画像検索・フィルタリング

**ユーザーストーリー:** 訪問者として、特定の画像を素早く見つけたい。そうすることで、大量の画像の中から目的の画像を効率的に探せる。

#### 受け入れ基準

1. 訪問者が検索キーワードを入力したとき、THE System SHALL ファイル名とTagに基づいて画像を検索する
2. 訪問者がTagフィルターを適用したとき、THE System SHALL 指定されたTagを持つ画像のみを表示する
3. 訪問者が撮影日フィルターを適用したとき、THE System SHALL 指定された期間内に撮影された画像のみを表示する
4. 訪問者が複数のフィルターを組み合わせたとき、THE System SHALL すべての条件に一致する画像のみを表示する
5. 検索結果が存在しない場合、THE System SHALL 適切なメッセージを表示する
6. 検索・フィルター条件をクリアしたとき、THE System SHALL すべての画像を再表示する
7. 検索・フィルター中、THE System SHALL リアルタイムで結果を更新する
8. フィルター適用時、THE System SHALL 無限スクロール機能を維持する

### 要件8: スライドショー機能

**ユーザーストーリー:** 訪問者として、画像を自動で順次表示したい。そうすることで、手動操作なしで画像を楽しむことができる。

#### 受け入れ基準

1. 訪問者がスライドショーボタンをクリックしたとき、THE System SHALL 自動スライドショーを開始する
2. スライドショー中、THE System SHALL 指定された間隔で次の画像に自動的に移動する
3. 訪問者がスライドショーを一時停止したとき、THE System SHALL 自動移動を停止する
4. 訪問者がスライドショーを再開したとき、THE System SHALL 自動移動を再開する
5. スライドショー中、THE System SHALL 手動での前後移動も可能にする
6. 最後の画像に到達したとき、THE System SHALL 最初の画像に戻るか停止するかを選択可能にする
7. 訪問者がスライドショーを終了したとき、THE System SHALL 通常の表示モードに戻る
8. スライドショー中、THE System SHALL 現在の画像位置を表示する

### 要件9: 認証・認可

**ユーザーストーリー:** システム管理者として、管理機能へのアクセスを制限したい。そうすることで、権限のないユーザーによる不正な操作を防げる。

#### 受け入れ基準

1. ユーザーがAdmin_Screenにアクセスしようとしたとき、THE System SHALL 認証を要求する
2. 認証されていないユーザーがAdmin_Screenにアクセスしようとしたとき、THE System SHALL ログイン画面にリダイレクトする
3. ユーザーが正しい認証情報を入力したとき、THE System SHALL Admin_Screenへのアクセスを許可する
4. 認証セッションが期限切れになったとき、THE System SHALL 再認証を要求する
5. Viewer_Screenにアクセスするとき、THE System SHALL 認証を要求しない
6. System_Adminがログインしたとき、THE System SHALL 全ユーザーの画像の完全な管理権限を付与する
7. Image_Managerがログインしたとき、THE System SHALL 全ユーザーの画像の閲覧・公開状態制御・ダウンロード権限を付与する
8. Regular_Userがログインしたとき、THE System SHALL 自分の画像のみの管理権限を付与する
9. ユーザーがログアウトボタンをクリックしたとき、THE System SHALL セッションを終了し、ログイン画面にリダイレクトする
10. ログアウト後、THE System SHALL 保存されている認証トークンをクリアする

### 要件12: セルフサインアップ（Regular_Userのみ）

**ユーザーストーリー:** 一般ユーザーとして、自分自身でアカウントを作成したい。そうすることで、管理者の手を煩わせずに画像管理システムを利用開始できる。

#### 受け入れ基準

1. 訪問者がサインアップページにアクセスしたとき、THE System SHALL メールアドレスとパスワードの入力フォームを表示する
2. 訪問者がメールアドレスとパスワードを入力してサインアップボタンをクリックしたとき、THE System SHALL reCAPTCHA v3トークンを自動生成し検証する
3. reCAPTCHAスコアが0.5以上のとき、THE System SHALL サインアップ処理を続行する
4. reCAPTCHAスコアが0.5未満のとき、THE System SHALL サインアップを拒否し、適切なエラーメッセージを表示する
5. サインアップが成功したとき、THE System SHALL 確認コードをユーザーのメールアドレスに送信する
6. ユーザーが確認コードを入力したとき、THE System SHALL アカウントを有効化する
7. アカウントが有効化されたとき、THE System SHALL 自動的にRegular_Userグループに追加する
8. アカウント有効化後、THE System SHALL 自動的にログインし、管理画面にリダイレクトする
9. パスワードが要件を満たさない場合、THE System SHALL 適切なエラーメッセージを表示する（最低8文字、大文字・小文字・数字・記号を含む）
10. 既に登録済みのメールアドレスでサインアップしようとしたとき、THE System SHALL 適切なエラーメッセージを表示する
11. サインアップページから、THE System SHALL ログインページへのリンクを提供する

### 要件10: サーバーレス構成

**ユーザーストーリー:** システム管理者として、サーバーレス構成を活用したい。そうすることで、運用コストを削減し、スケーラビリティを確保できる。

#### 受け入れ基準

1. 画像がアップロードされたとき、THE System SHALL AWS Lambda関数を使用して処理する
2. 画像のMetadataが作成されたとき、THE System SHALL AWS DynamoDBに保存する
3. フロントエンドがデプロイされるとき、THE System SHALL AWS S3とCloudFrontで静的ホスティングする
4. APIが呼び出されたとき、THE System SHALL AWS API Gatewayを通じて処理する
5. 認証が必要なとき、THE System SHALL AWS Cognitoを使用する

### 要件11: セキュリティ

**ユーザーストーリー:** ユーザーとして、画像が安全に管理されることを確認したい。そうすることで、プライバシーとセキュリティが保護される。

#### 受け入れ基準

1. ユーザーがAdmin_Screenにアクセスするとき、THE System SHALL 適切な認証を要求する
2. 画像がアップロードされるとき、THE System SHALL ファイルの内容を検証し、悪意のあるファイルを拒否する
3. 画像にアクセスするとき、THE System SHALL ユーザーの権限を確認する
4. データが転送されるとき、THE System SHALL HTTPS暗号化を使用する
5. 機密データが保存されるとき、THE System SHALL 適切な暗号化を適用する
6. Regular_Userが他のユーザーのデータにアクセスしようとしたとき、THE System SHALL アクセスを拒否する
